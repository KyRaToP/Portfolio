# Portfolio Website --- Design Specification

**Version:** 1.0\
**Status:** Approved design direction\
**Purpose:** Design and implementation specification for a personal
freelance developer portfolio.\
**Implementation target:** Cursor + existing universal freelance project
template.

------------------------------------------------------------------------

# 1. Project Goal

Create a premium, modern personal developer portfolio that presents the
developer as a capable freelance developer rather than as a beginner.

The website must simultaneously:

1.  Present the developer clearly.
2.  Showcase three existing real projects.
3.  Explain what the developer can build for clients.
4.  Demonstrate technical competence through real project evidence.
5.  Provide direct paths to GitHub, live demos and contact.
6.  Work perfectly on desktop, tablet and mobile.
7.  Be visually distinctive without becoming overloaded with effects.
8.  Be maintainable and easy to extend with future projects.

The portfolio is both:

-   a personal developer website;
-   a sales/presentation tool for freelance work.

------------------------------------------------------------------------

# 2. Approved Design Direction

The approved direction is a combination of:

-   **Bento-grid visual composition** from Reference Image 1.
-   **Project-first presentation** from Reference Image 2.
-   **Case-study-oriented project pages**.
-   **Developer / digital-studio positioning** rather than a generic CV
    website.

The visual language should feel:

> modern, premium, technical, confident, clean, slightly experimental.

It must NOT feel like:

-   a copied template;
-   a generic SaaS landing page;
-   a gaming website;
-   an AI-generated portfolio full of random effects;
-   a personal website dominated by an illustrated/avatar character.

# 23. Accent Colors

Do NOT copy the reference colors.

Use a restrained original accent system.

Recommended direction:

-   electric blue;
-   violet;
-   cool cyan;
-   optional warm accent for small highlights.

The palette must remain mostly monochrome with controlled accent colors.

Avoid using many unrelated saturated colors.

Gradients should be ambient and subtle.

They should support the composition rather than become the composition.

------------------------------------------------------------------------

# 24. Typography

Use a modern sans-serif.

Preferred options:

-   Inter;
-   Geist;
-   Manrope;
-   another comparable modern sans-serif.

Use:

-   very large display typography for major headings;
-   medium/large headings for cards;
-   compact readable body text;
-   small uppercase metadata labels.

Typography should create hierarchy without excessive font weights.

------------------------------------------------------------------------

The Bento Grid is a core visual principle.

Desktop should use an asymmetric grid.

Use Bento where it improves visual hierarchy.

------------------------------------------------------------------------

# 26. Cards

All major cards should share a common design language:

-   rounded corners;
-   subtle border;
-   dark surface;
-   controlled gradient/ambient lighting;
-   consistent internal padding;
-   overflow hidden;
-   strong image treatment.

Avoid excessive glassmorphism.

Avoid giant blurred blobs behind every element.

Avoid excessive shadows.

------------------------------------------------------------------------

# 27. Decorative Elements

Allowed:

-   very subtle grid lines;
-   thin technical lines;
-   small dots;
-   subtle noise/grain;
-   ambient gradient glow;
-   small geometric elements;
-   occasional floating UI details.

Not allowed:

-   dozens of stars;
-   random symbols;
-   decorative elements with no design purpose;
-   distracting particles;
-   heavy background animation.

Decorative elements must remain secondary to content.

------------------------------------------------------------------------

# 28. Animations

Animations should feel premium and intentional.

Recommended:

-   initial fade/slide reveal;
-   staggered card reveal;
-   subtle hover lift;
-   image scale on hover;
-   gradient movement;
-   smooth navigation transitions;
-   active navigation indicator;
-   subtle CTA interaction.

Animation principles:

-   short;
-   smooth;
-   restrained;
-   interruptible;
-   accessible.

Respect `prefers-reduced-motion`.

Do not animate everything.

------------------------------------------------------------------------

# 29. Project Hover Interaction

On desktop:

-   card slightly lifts;
-   image subtly scales;
-   gradient changes minimally;
-   CTA becomes more visible.

Do not use:

-   aggressive 3D tilt;
-   spinning cards;
-   cursor-following effects everywhere;
-   excessive parallax.

------------------------------------------------------------------------

# 30. Responsive Design

Must be designed for:

-   320px;
-   375px;
-   390px;
-   430px;
-   768px;
-   1024px;
-   1280px;
-   1440px+.

Mobile is not a compressed desktop.

On mobile:

-   Bento grid becomes a controlled vertical composition;
-   cards become one column;
-   typography scales down;
-   navigation becomes compact;
-   screenshots remain readable;
-   buttons remain easy to tap;
-   animations are reduced where appropriate.

------------------------------------------------------------------------

# 31. Images and Project Assets

Use real screenshots from the actual projects.

exist.

-   browser mockup for web projects;
-   phone mockup for Mini App;
-   Telegram chat screenshots for Bot;
-   large cropped screenshots inside cards;
-   image gallery inside Case Studies.

For videos/GIFs:

-   use only when they demonstrate real functionality;
-   keep previews short;
-   provide poster/fallback image.

-   concise;

# 40. Development Workflow for Cursor

Cursor must NOT attempt to implement the whole website in one step.

Implementation order:

### Phase 1 --- Audit

Analyze existing template and repository.

Do not modify code.

### Phase 2 --- Architecture

Propose component/page/data structure.

Wait for approval.

### Phase 3 --- Design System

Implement typography, colors, spacing, cards, buttons and base styles.

### Phase 4 --- Layout

Implement:

-   Header;
-   Hero;
-   Bento composition;
-   Projects;
-   Services;
-   About;
-   Contact;
-   Footer.

### Phase 5 --- Project pages

Implement the three Case Studies.

### Phase 6 --- Responsive

Test and refine desktop/tablet/mobile.

### Phase 7 --- Animation

Add restrained animations only after layout and functionality work
correctly.

### Phase 8 --- Quality

Check:

-   console errors;
-   broken links;
-   responsive behavior;
-   accessibility;
-   SEO;
-   performance;
-   images;
-   navigation;
-   Git status.

### Phase 9 --- Deploy

Deploy only after local validation.
